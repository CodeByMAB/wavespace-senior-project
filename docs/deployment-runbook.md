# Deployment runbook — Wavespace Bitcoin Wallet

End-to-end release process for the Expo / EAS managed app (`com.wavespace.wallet`).

## EAS project and OTA URL

After **`eas init`**, replace the placeholder Expo project ID in **`app.json`** so these stay in sync:

- `expo.extra.eas.projectId`
- `expo.updates.url` → must be `https://u.expo.dev/<projectId>`

The placeholder ID in the repo is only for structure; production builds must use the real ID from your Expo account.

**Breez SDK / native changes:** Any upgrade to native modules (including `@breeztech/breez-sdk-spark-react-native`) requires a **full store build** and resubmission. **OTA (`eas update`) is only for JavaScript and asset changes** compatible with the existing native binary.

## Secrets and credentials

- Set **`BREEZ_API_KEY`** as an EAS Secret (do not commit real keys):

  ```bash
  eas secret:create --name BREEZ_API_KEY --value "<your-key>" --type string
  ```

  **Development / preview device builds:** `app.config.js` reads this variable on the **EAS build worker** and writes `expo.extra.breezApiKey` into the native manifest. If the secret was missing when you built the dev client, the binary has an empty key until you add the secret and **rebuild** (`eas build --profile development`). Separately, when you load JS from Metro on your Mac, **`EXPO_PUBLIC_BREEZ_API_KEY`** in a local `.env` is inlined into the JavaScript bundle—use that for quick local iteration without a new store/dev binary, after `npx expo start --dev-client --clear`.

  The `eas.json` production profile documents this requirement; production builds must resolve the secret in EAS (replace the placeholder `"..."` in `env` or rely on EAS Secrets as your team prefers).

- **`google-service-account.json`** (Play Console API access) must live at the repo path referenced in `eas.json` **locally / in CI only**. It is **gitignored** and must never be committed.

## 1. Pre-flight checks

- All feature work for the release is **Done**.
- **Tests:** `npm test` (Vitest) and Maestro E2E (`npm run test:e2e` / `scripts/qa-e2e-maestro.sh`) pass.
- **`BREEZ_API_KEY`** is configured for EAS production builds.
- **`app.json`** `updates.url` / `extra.eas.projectId` match your Expo project after `eas init`.

## 2. Production build

```bash
eas build --platform ios --profile production
eas build --platform android --profile production
```

## 3. Internal / beta testing

- **iOS:** Distribute with **TestFlight** (e.g. `eas submit --platform ios --profile production` after the iOS build completes).
- **Android:** Distribute via **Play Console Internal testing** track (see `submit.production.android.track`: `internal`).

## 4. Beta sign-off

Target: **~4 weeks**, **50–100** testers, **crash rate &lt; 0.1%** (or your org’s bar). Collect feedback on payments, recovery, and performance.

## 5. Store submission

```bash
eas submit --platform ios --profile production
eas submit --platform android --profile production
```

Fill in **`eas.json` → `submit.production.ios`**: `ascAppId` and `appleTeamId` after the App Store Connect app record exists. Replace placeholder Apple ID if needed.

## 6. OTA-only updates (JS / assets only)

```bash
eas update --branch production --message "Describe the change"
```

**Reminder:** Native or Breez SDK changes require repeating steps **2–5** (full store build + submit).

## App Store Connect checklist (iOS)

- **Category:** Finance (or the closest appropriate category).
- **Age rating:** Complete the questionnaire honestly (financial themes, etc.).
- **Privacy Policy URL:** Must match a **live** public page (see `docs/privacy-policy.md`; `app.json` `privacyPolicyUrl` should point to the same URL).
- **Export compliance:** App uses standard OS encryption only; `ITSAppUsesNonExemptEncryption` is set to `false` in `app.json` — confirm answers in App Store Connect align with your legal review.
- **Screenshots:** Required per **device size** (see below). Capture from **simulator** or device at required resolutions.

## Google Play Console checklist (Android)

- **Category / content:** Finance / payments as appropriate.
- **Data safety form:** Align with `docs/privacy-policy.md` (no Wavespace server analytics; third-party Breez; camera for QR; biometrics on-device).
- **Privacy policy URL:** Same public URL as iOS.
- **Screenshots** and **feature graphic** per requirements below.

## Legal URLs before submission

Host **`docs/privacy-policy.md`** and **`docs/terms-of-service.md`** at **public HTTPS URLs**. Update:

- Store listings (both platforms).
- `app.json` → `privacyPolicyUrl` (already points at `https://www.wavespace.com/privacy-policy` — change to your real URL when the site is live).
